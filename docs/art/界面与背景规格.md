# 界面与背景规格

> 状态：第一版灰盒规格。逻辑布局已冻结，美术细节仍可迭代。

## 分辨率职责

`960×540` 是 Godot 的逻辑布局画布，不是最终输出清晰度。项目使用 `canvas_items` 渲染与 `expand` 宽高比策略：控件以逻辑坐标排版，窗口可以输出到 1080p、1440p 或更高分辨率，宽屏增加的是两侧环境区域。

| 项目 | 规格 |
| --- | --- |
| UI 逻辑画布 | `960×540` |
| 桌面精确排版区域 | 中央 16:9 |
| 2K 背景核心 | `2560×1440` |
| 20:9 手机背景母版 | `3200×1440`，中央保留完整 `2560×1440` |
| 贴图采样 | 像素贴图最近邻；高清背景按最终观感单独设置 |
| 文字 | Godot 字体实时渲染，不烘入图片 |

如果生成工具不能直接输出 20:9，先完成 16:9 核心图，再以锁定中央内容的方式向左右延展。禁止分别生成两张构图不同的桌面版和手机版背景。

## 中央安全区

- 所有按钮、牌面、头像、计分和关键文字都位于中央 `960×540`。
- 超宽屏额外区域只放墙面、窗帘、书架等可裁切装饰。
- 背景全屏覆盖；交互层保持中央，不随额外宽度横向散开。
- Android 阶段再读取系统安全区域，将边缘返回按钮等少量控件向内收；牌桌核心布局不变。

## 生产边界

生成模型可以提供：

- 无人物、无牌、无文字、无 UI 的房间与桌体背景。
- 不承载语义的静态家具和前景装饰。
- UI 边框与材质的风格参考稿。

Godot 和确定性图集负责：

- 所有文字、数字、按钮、面板状态和焦点反馈。
- 扑克牌，以及麻将牌的 3D 几何、确定性牌面图集、牌墙、牌河和选中状态。
- 人物占位、头像框、对话气泡、提示、托管和结算。
- 光晕、按压、移动、淡入淡出等运行时效果。

## 当前灰盒占位

- 大厅：左右玩法入口、中央人物位、顶部资料栏和底部导航。
- 斗地主：三座位、20 张手牌、中央出牌区、顶部计分和底部操作栏。
- 麻将：2D 桌面背景、透明 3D 牌层、四座位、14 张可点击手牌、四方牌墙与牌河、中央信息盘和吃碰杠和牌操作栏。

## 麻将电脑端尺寸

初版按电脑端定标，默认窗口使用 `1280×720`，重点兼容 1080p 与 2K 全屏。提升输出分辨率只提高 3D 子视口清晰度，不放大牌的世界尺寸。

| 元素 | 当前基线 |
| --- | --- |
| 玩家 14 张手牌 | 占中央安全区宽度约 `50%`；基准牌模 `84%`；面向屏幕、连续并排 |
| 四方牌墙 | 基准牌模 `48%`，沿桌面标定线排列 |
| 四方牌河 | 基准牌模 `58%`，落在四个紫色标定框内 |
| 点击区域 | 仅玩家手牌启用；与牌体一致，选中后上抬 |
| 手机阶段 | 以后调整安全区、相机和触控容错，不按 2K 像素数直接放大牌 |

青色绒布内框、黄色安全区、橙色牌墙线、紫色牌河框和绿色手牌线都来自同一份标定数据，可通过麻将界面的“标线”按钮开关。具体合成和模块边界见[麻将混合渲染](../architecture/麻将混合渲染.md)。

开发预览可以直接指定启动场景：

```bash
./scripts/godot.sh --path . -- --preview=doudizhu
./scripts/godot.sh --path . -- --preview=mahjong
```

正式背景生成提示词见[美术提示词库](../prompts/README.md)。
