# 2026-08-01-013：斗地主试玩闭环

- 状态：已完成
- 日期：2026-08-01
- 负责人：Codex
- 关联文档：[斗地主规则](../rules/斗地主规则.md)、[程序实现规划](../architecture/程序实现规划.md)

## 目标

把现有斗地主规则引擎、应用会话、本地豆子与 Godot 灰盒牌桌接成首个可独立试玩的 Windows 纵向切片：玩家可从大厅进入，对两名 AI 完成叫抢、出牌、结算、存档与再来一局。

## 范围

本任务包含大厅档案显示与免费补给、斗地主真实手牌和公开状态、叫抢/提示/不出/出牌/托管、AI 回合推进、结算弹窗、再来一局、活动对局恢复、必要的界面边界测试、试玩说明和 Windows x64 导出验证。

本任务不接入三种麻将玩法，不重做现有背景、美术布局、麻将 3D 桌面、固定相机或 `MahjongTableCalibration`，也不加入商城、联网、角色成长、复杂动画或音效。

## 关键决策

- Godot 表现层只消费 `DoudizhuGameSession` 的玩家视图、合法出牌和规则事件；按钮禁用、提示与托管都复用该权威来源。
- 本地玩家固定为座位 0，两名对手由现有基础 AI 驱动；AI 以短暂节拍连续推进，避免用表现层模拟规则状态。
- 每个已接受操作后保存最小恢复记录；结算后由应用层经济边界更新豆子与战绩并清除活动对局。
- 第一版继续使用现有程序文字牌面与灰盒样式，优先交付完整、可验证的操作闭环。

## 实际改动

- 新增 `DoudizhuTableController`，把现有 `DoudizhuGameSession` 接入 Godot 牌桌；真实显示玩家手牌、三家剩余牌数、地主身份、底牌、当前行动者、上一手、倍数与豆子。
- 叫地主/抢地主/放弃、选牌、出牌、不出、提示和托管均提交应用层命令或消费其合法操作列表；Godot 层没有复制牌型与压制判断。
- 两名对手按可见信息由现有基础 AI 分步行动；托管玩家复用同一个 AI 与合法操作来源，保留可观察的行动节拍和中途关闭能力。
- 接入规则事件文案、结算弹窗、胜负/春天/倍数/豆子变化、返回大厅和再来一局；豆子不足时“再来一局”会明确执行免费补给。
- `Bootstrap` 接入 `user://profile-v1.json` 本地档案，大厅显示真实豆子、战绩、补给状态和未完成牌局入口；每个已接受操作保存最小恢复记录，结算后更新档案并清除活动牌局。
- 调整现有斗地主灰盒的必要节点与操作区，保留背景和总体布局；麻将入口改为“桌面预览（玩法接入中）”，未修改麻将 3D 层、相机、标定或摆位。
- 增加可自动托管并在结算时退出的无头场景烟测参数，用真实 Godot 控制器验证完整牌局；同步根 README 当前状态、试玩说明和工程目录。
- 生成 Windows x64 Release 导出及包含 EXE、PCK 和 .NET 运行时目录的试玩压缩包。
