# 2026-08-01-018：麻将本地恢复与战绩反馈

- 状态：已完成
- 日期：2026-08-01
- 负责人：Codex
- 关联文档：[产品路线图](../product/产品路线图.md)、[架构总览](../architecture/架构总览.md)、[四人日麻 Godot 东风战闭环](2026-08-01-017-四人日麻Godot东风战闭环.md)

## 目标

为三种麻将补齐完全本地的未完成对局恢复、分模式战绩和最小分数/豆子反馈，同时将本地档案从 schema v1 最小迁移到 v2，不影响已有斗地主档案。

## 范围

本任务包含三个独立麻将会话的确定性种子+已接受命令重放、大厅续局入口、结算后的分模式对局数/胜局/累计得分、豆子变化反馈，以及 schema v1 迁移测试。

本任务不保存规则快照、状态哈希或镜像状态，不增加网络、云存档、商城、广告或成长系统。

## 关键决策

- 恢复的唯一权威输入是模式、种子、玩家座位与已接受命令序列；恢复时从规则引擎初始状态顺序重放。
- 三种玩法仍由各自会话适配器重放命令，公共层只承载可序列化命令和模式路由。
- 战绩保存规则结算得分；豆子反馈由本地经济边界一次性应用，Godot 只显示结果。
- schema v1 的明确故障模型是旧档缺少麻将战绩与续局字段；迁移只补齐这些默认值并升版号，保留豆子、斗地主战绩和未完成斗地主，未知版本仍明确拒绝。

## 实际改动

- 新增可序列化的 `MahjongRecoveryState`、命令种类与实体牌记录，完整覆盖通用摸打/吃碰杠胡、四川换三张/定缺、日麻立直/九种九牌命令。
- 大众、四川、日麻三个适配器只记录规则引擎已接受的玩家或 AI 命令；模式工厂按原种子建立新引擎并由各适配器顺序重放，非法命令直接拒绝恢复。
- `LocalPlayerProfile` 升级为 schema v2，新增大众/四川/日麻各自的局数、胜局和累计规则得分，以及一份未完成麻将记录；`JsonProfileStore` 对 v1 执行单向最小迁移。
- 三种适配器在终局快照中提供本地座位得分与胜负；本地经济边界对大众/四川按规则分直接反馈豆子，日麻按 100 点折算 1 豆，余额仍不低于零。
- Godot 麻将桌在开局和每个已接受命令后使用唯一保存入口；大厅将已保存模式标为“继续”并暂停其他麻将新局，结算层显示本地得分、豆子变化和分模式战绩。
- 同步根 README 现状/结构和架构文档，明确麻将恢复不序列化规则快照、事件或状态哈希。

## 验证

- `./scripts/dotnet.sh test tests/Game.Application.Tests/Game.Application.Tests.csproj --no-restore`：28 项全部通过；三种麻将均在中途创建恢复记录，原会话与恢复会话逐命令产生相同事件并运行到同一终局；非法重放被拒绝。
- schema v1 迁移测试确认豆子、斗地主战绩与可恢复对局保留，再次保存写入 schema v2；麻将记录 JSON 往返后可重放。
- 本地经济测试分别验证大众、四川、日麻只更新对应模式战绩、得分和豆子折算。
- `./scripts/verify.sh`：文档治理与忽略规则通过；全解决方案构建 0 警告、0 错误；121 项 .NET 测试全部通过；Godot 编辑器/大厅/斗地主/麻将基础启动与三种固定种子真实整局烟测全部通过。
