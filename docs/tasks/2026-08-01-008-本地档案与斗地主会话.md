# 2026-08-01-008：本地档案与斗地主会话

## 目标

建立斗地主纵向切片所需的最小应用层边界：本地豆子、免费补给、版本化 JSON 档案、安全保存、对局会话编排和基于确定性命令重放的对局恢复。

## 范围

本任务包含 `Game.Application` 对斗地主模块的编排引用、本地档案 DTO、豆子与战绩更新、JSON 主文件/备份保存、斗地主玩家视图、AI 推进、接受命令记录与恢复，以及独立应用层测试项目。

本任务不包含商城、充值、广告、联网账号、复杂成长、云同步、多个备份链、状态哈希或 Godot UI 接线。

## 关键决策

- 初始与免费补给额度均为 3,000 豆；低于最低入场需求时可立即补给，无次数、广告或等待限制。
- 规则结算保持零和；应用到本地玩家豆子时最低为 0，随后可免费补给，不让余额反向修改规则胜负或倍数。
- 存档模式版本从 1 开始，只迁移实际存在的旧版本；当前没有旧版本，因此未知版本明确拒绝，不预建空迁移框架。
- 对局恢复只保存随机种子、规则配置、玩家座位和全部已接受命令；恢复时重新执行同一个规则引擎，不保存镜像规则状态或状态哈希。
- 存档额外校验的故障模型是进程在写文件期间退出、磁盘写入中断或主 JSON 损坏。收益是避免覆盖最后可读档案；验证方式是临时文件回读、主文件损坏时加载单份备份的测试。

## 实际改动

- `Game.Application` 增加对 `Game.Doudizhu` 的引用，并实现 `DoudizhuGameSession`：仅允许玩家控制本地座位，逐回合推进 AI，输出玩家只读观察和合法出牌。
- 新增可 JSON 化的斗地主恢复记录，只保存种子、底分、本地座位与已接受命令；恢复时重建规则引擎并逐条重放，任何不再合法的命令都会拒绝恢复。
- 新增模式版本 1 的 `LocalPlayerProfile`，保存豆子、斗地主局数/胜局和一局活动中的斗地主恢复记录。
- 新增 `LocalProfileEconomy`：初始/补给 3,000 豆，余额低于最低入场需求时可即时免费补给；规则输赢应用后余额最低归零并更新战绩。
- 新增 `JsonProfileStore`：写同目录临时文件、回读验证、保留一份最后可读主档备份后替换正式文件；主档损坏时读取备份，未知模式版本明确拒绝。
- 若当前主档已损坏，后续保存不会用损坏内容覆盖最后可读备份，避免恢复后再次保存时丢失唯一完好副本。
- 新增 `Game.Application.Tests` 项目并加入解决方案，覆盖经济、档案、备份、版本拒绝、恢复记录验证、会话权限与确定性重放。
