# 2026-08-01-014：麻将公共应用与表现边界

- 状态：已完成
- 日期：2026-08-01
- 负责人：Codex
- 关联文档：[程序实现规划](../architecture/程序实现规划.md)、[麻将混合渲染](../architecture/麻将混合渲染.md)

## 目标

建立三种麻将共用的应用层与表现数据边界：统一模式、玩家座位、AI 调度、动画节拍、保存入口和场景生命周期，同时让大众、四川与日麻保持独立会话适配器。

## 范围

本任务包含纯 C# 麻将应用契约、只读桌面表现数据、合法操作选项和三个独立会话适配器的公共接入方式，以及聚焦命令映射和状态转换的应用层测试。

本任务不包含 Godot 牌桌交互闭环、存档 schema 升级或任何规则扩展；三种玩法的 Godot 接入在后续分阶段任务中完成。

## 关键决策

- 公共边界只暴露模式无关的桌面只读数据、操作选项和会话生命周期，不根据模式重新判断合法性。
- 大众、四川、日麻各自适配本模式规则快照、合法操作和 AI，不建立包含玩法条件的巨型控制器。
- 提示、托管、AI 和后续 Godot 按钮均消费同一份规则层合法操作列表。

## 实际改动

- 新增麻将公共会话契约与工厂，统一模式、确定性种子、本地玩家座位、玩家操作、AI 推进、提示/托管入口与已接受命令的变更通知。
- 新增只读 `MahjongSessionView`、四座手牌可见性、副露、牌河、牌墙数量、HUD 字段、结算摘要和精确合法操作选项；对家暗牌仅保留数量与牌背信息。
- 新增统一摸牌、弃牌、鸣牌、宣言、和牌和结算动画事件与首版节拍，供 Godot 只读消费。
- 新增 `StandardMahjongGameSession`、`SichuanMahjongGameSession` 和 `RiichiMahjongGameSession`；每个适配器分别调用自身规则引擎和既有 AI，负责本模式快照、命令和表现事件转换，公共控制器没有玩法合法性分支。
- 新增 7 项麻将应用边界测试，覆盖三种适配器、暗牌可见性、精确操作映射、四川换三张/定缺阶段、日麻 HUD 和保存通知边界。
- 更新应用层项目引用、架构规划与根 README 工程目录。
