## 目标

承载《方寸牌社》的长期人工试玩和逐点交互打磨：根据实机反馈定位具体问题，实施最小、可观察、容易回退的调整，并在每个稳定批次记录反馈、实际改动、自动验证和仍需人工确认的项目。

## 范围

本任务主要覆盖麻将玩家手牌、牌墙、牌河、副露、宝牌与 HUD 的布局和尺寸，按钮、选牌、点击命中区与弹层交互，动画节拍与状态表达，以及 `960×540` 核心安全区内的可读性。只有收到对应反馈时才处理斗地主表现遗留。

本任务不主动扩展或重做规则，不推翻固定相机、背景构图及 2D 桌面加透明 3D 牌层方案，不为未完成的正式美术提前建立资产抽象。

## 关键决策

- 本任务允许连续承载多轮人工调校，但每条反馈保持独立定位，每个稳定批次分别记录和验证，不把无关问题混成重构。
- 普通布局和交互选择在既有表现边界内直接实施；只有正式规则文档冲突且会改变牌局结果时才暂停确认。
- 未经用户实机确认的批次不提交、不推送，也不标记为稳定完成；普通小调整不重复导出 Windows 包。

## 反馈分类与处理边界

每条反馈先归入以下一类，再沿现有权威边界定位：

1. 规则结果错误。
2. 应用层命令映射错误。
3. 显示信息错误。
4. 布局或尺寸问题。
5. 点击、选牌或按钮交互问题。
6. 动画节拍或状态表达问题。
7. 存档或续局问题。

- 纯表现问题只改表现层；只有正式规则文档冲突且会改变牌局结果时才暂停确认。
- `MahjongTableCalibration` 继续作为所有麻将桌面位置、朝向和投影的唯一来源，标线与真实牌复用同一标定数据。
- `MahjongBoard3D` 只消费只读表现数据；UI、提示、托管和按钮不重新判断任何玩法合法性。
- 大众、四川与日麻保留独立会话适配器，不缓存第二份规则状态，不加入状态哈希、镜像状态或额外恢复路径。
- 日麻“上一局”面板继续只读取规则快照结果，不在表现层重算役、符番或支付。

### 批次 1：斗地主叫抢显示、牌面与 AI 节拍

- 反馈：玩家点“不叫”后仍看到“抢地主”选项；叫抢阶段或托管时玩家手牌会变灰；中央出牌使用文字摘要而非正常卡牌；机器人连续操作间隔过短且固定，无法看清上一手。
- 分类：叫抢项为显示信息错误（规则层已有“不叫后不再获得抢地主资格”的权威实现和回归测试）；手牌和中央出牌为显示信息错误；机器人间隔为动画节拍问题。
- 实际调整：叫抢操作栏只在本地玩家当前确实可叫抢且未托管时显示，不再把机器人回合的提示以灰色按钮展示给玩家；不可点击的玩家手牌继续阻止输入，但复用正常牌面颜色和底板，不再用禁用灰态表达回合状态；中央出牌区改为逐张真实 Godot 卡牌节点，复用玩家手牌的牌面、花色与边框风格，并按牌数调整重叠间距；普通机器人与托管回合的等待改为约 `1.1～1.8` 秒随机节拍，快速自动验证仍保留毫秒级等待。
- 自动验证：Godot 主项目构建通过，0 警告、0 错误；斗地主规则项目 39 项测试全部通过；真实 Godot 斗地主以 `--autoplay --fast-autoplay --quit-on-finish` 从开局运行到结算并正常退出；解决方案格式、文档治理、`git diff --check` 与工作树检查通过。
