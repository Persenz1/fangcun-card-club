# 2026-08-01-003：界面灰盒与美术提示词

- 状态：已完成
- 日期：2026-08-01
- 负责人：Codex
- 关联文档：[美术与内容文档](../art/README.md)、[程序实现规划](../architecture/程序实现规划.md)

## 目标

完成大厅、斗地主和麻将三个 960×540 逻辑画布下的可交互灰盒，冻结第一版界面安全区与背景构图需求，并将可复用的美术生成提示词按资产类型归档到 `docs/prompts/`。

## 范围

本任务包含：

- 三个灰盒界面的场景切换与主要交互区域。
- 斗地主最多 20 张手牌及三座位布局演示。
- 四人麻将桌、牌墙/手牌及主要操作区布局演示。
- 16:9 桌面布局、宽屏延展和移动设备安全区约定。
- 大厅、斗地主、麻将背景的生产提示词及通用负面约束。
- 三张无人物、无牌面、无 UI 的首轮背景候选生成、留档与灰盒接入。

本任务不包含：

- 正式规则状态机、AI、结算与存档接入。
- 正式人物和 UI 位图的生成。
- 2K/20:9 正式背景母版制作；本任务只保留并接入构图候选。
- 正式扑克牌、麻将牌图集与音效。

## 关键决策

- `960×540` 仅作为布局逻辑画布，最终渲染分辨率跟随窗口；背景保留至少 `2560×1440` 的生产母版。
- 核心交互保持在中央 16:9 安全区；移动宽屏的额外区域只承载可裁切背景与非关键装饰。
- GPT 只负责无文字、无人物、无牌面、无交互状态的环境底图；所有功能性界面由 Godot 控件实现。
- 灰盒使用模拟数据验证布局，不等待规则模块完成，也不在表现层复制规则判断。

## 实际改动

- 将启动场景改为宽屏背景与中央 `960×540` 安全区结构，并把拉伸策略改为 `expand`。
- 新增大厅、斗地主和四人麻将三个独立场景；实现大厅跳转、免费补给、返回、托管、提示和各操作按钮的灰盒反馈。
- 使用固定种子生成斗地主 20 张模拟手牌，使用固定示例牌生成麻将 14 张手牌；表现层只展示交互意图，不实现牌型或向听规则。
- 新增共享 `GrayboxTheme`，统一面板、按钮、焦点、悬停和按压状态。
- 新增 `docs/prompts/`，按背景、交互 UI 和人物分类；归档通用背景基线、三个场景提示词、UI 装饰参考提示词和生成记录。
- 新增界面与背景规格、背景候选资产清单，冻结逻辑画布、2K 核心和 20:9 母版边界。
- 使用 Codex 内置 `image_gen` 结合概念图生成三张 `v001` 背景候选，保存到 `game/assets/backgrounds/candidates/` 并接入三个场景及 `deep-night` 主题。
- 扩展验证脚本，分别启动大厅、斗地主和麻将路径；扩展文档检查，强制提示词包含背景、UI 和人物分类 README。
- Windows 导出排除 `美术概念/`，避免把仅供参考的原始概念图打入成品。
