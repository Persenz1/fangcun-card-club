# 麻将混合渲染

> 状态：技术原型基线。首版以 Windows 电脑端为主。

## 目标

麻将房间和牌桌继续使用固定视角的 2D 背景，只有麻将牌使用 3D 几何体。这样既保留背景概念图的氛围与构图，也让手牌、牌墙、牌河和后续副露具有一致厚度、角度与移动空间。

这套方案只规定表现层，不实现麻将规则。规则状态由纯 C# 麻将模块提供，Godot 层只根据应用层 `MahjongSessionView` 只读数据摆牌，并以精确合法操作 ID 提交玩家意图。

## 合成层级

| 层级 | 实现 | 职责 |
| --- | --- | --- |
| 背景 | 2D `TextureRect` | 房间、固定桌体、桌沿和环境光影 |
| 麻将牌 | 透明 `SubViewport` + 3D 固定相机 | 手牌、四方牌墙、牌河及其位姿 |
| HUD | 2D Godot 控件 | 座位、分数、按钮、向听、提示和弹窗 |

透明 3D 层位于背景与 HUD 之间。桌体不重复建模，HUD 也不进入 3D 世界。若正式背景的近侧桌沿确实需要遮住牌脚，再增加一张局部前景遮罩；没有遮挡问题时不新增该层。

## 相机与分辨率

- 相机位置、视野角和朝向固定，不提供旋转、缩放或自由观察。
- `960×540` 只承担逻辑排版。默认桌面窗口为 `1280×720`，全屏重点验证 `1920×1080` 和 `2560×1440`。
- 3D 子视口按当前窗口的 16:9 核心区域以原生像素渲染：1280×720 窗口对应 1280×720，2K 对应 2560×1440。
- 超宽屏仍只扩展两侧 2D 环境，牌桌和麻将保持在中央 16:9 安全区。
- 分辨率变化只改变渲染清晰度，不改变麻将在桌面上的世界尺寸。

`Mahjong3DLayer` 负责子视口分辨率与输入坐标换算；`MahjongBoard3D` 只接受当前 `MahjongSessionView` 和可选动画事件，负责固定相机、灯光和真实手牌/摸牌/副露/牌河/牌墙/宝牌节点的位姿；`MahjongTile3D` 负责单张牌的共用几何、牌面与选中反馈。三者不保存第二份对局规则状态。

## 桌面标定

- `MahjongTableCalibration` 是当前背景的唯一摆位基准，保存 `960×540` 下的绒布内框、摆牌安全区、四面牌墙线、四个牌河框、四家手牌线、四家副露线、宝牌指示线和中央信息盘。
- `MahjongTableGuide` 直接读取同一组数据绘制开发标线；麻将界面的“标线”按钮可以整体显示或隐藏。
- 桌面上的 3D 牌先取得逻辑画布标定点，再由固定相机射线投到 `Y=0` 桌面平面。禁止另存一套近似世界坐标。
- 青线表示背景绒布内框，黄线表示麻将安全区，橙线表示牌墙中心线，紫框表示牌河，绿线表示玩家手牌。
- 玩家手牌是例外：位置仍由标定线决定，但牌面保持与屏幕平行，不继承桌面倾角。

## 电脑端尺寸基线

- 玩家 14 张手牌横向占中央 16:9 区域约 `50%`，使用基准牌模的 `84%`，牌面朝向屏幕并按实际牌宽连续排列。
- 玩家手牌保留完整鼠标点击体积；被选中的牌只向上抬起。
- 牌墙和牌河分别使用基准牌模的 `48%` 与 `58%`，作为次级信息，不与手牌争夺视觉重心。
- 只有玩家手牌启用射线拾取与碰撞体；牌墙和牌河不创建无用的交互碰撞。
- 中央信息盘必须给四方牌河留出可见间距，不用放大麻将来弥补 HUD 遮挡。

Android 适配以后单独调整安全区、相机参数和触控容错，不因手机像素分辨率高就直接放大世界中的麻将。

## 资产与运行时边界

- 当前技术原型使用共用低面数方牌和程序文字，验证厚度、透视、层级与点击。
- 正式牌模可以替换几何和材质，但必须保持统一原点、朝向、比例与碰撞尺寸约定。
- 万、筒、条、风牌和三元牌属于规则语义资产，正式版本使用人工校对的确定性图集，不让生成模型直接决定牌面内容。
- 所有牌共享模型与材质资源；每张牌只持有必要的牌面和变换数据。
- 不使用刚体、牌堆物理、动态桌面或自由相机。摸牌、出牌、理牌动画直接插值确定的目标位姿。

## 当前原型限制

- 牌模还是无倒角的 `BoxMesh`，正式美术阶段再决定倒角与侧面细节。
- 牌面是 `Label3D` 文字占位，尚未接入正式图集。
- 2D 桌面无法接收真实 3D 阴影；当前用材质明暗和厚度建立落桌感。
- 相机与摆位针对当前麻将背景候选调校，替换正式背景时需要按同一透视基准复核一次。
